Large Language Model-Driven Structured Output: A Comprehensive Benchmark and Spatial Data Generation Framework

المخرجات المنظمة بقيادة النماذج اللغوية الكبيرة: معيار شامل وإطار توليد البيانات المكانية

👤 D. Li, Y. Zhao, Z. Wang, C. Jung, Z. Zhang 📄 ISPRS Int. J. Geo-Inf., 2024, Vol. 13(11), 405 🔗 10.3390/ijgi13110405 ✓ CC BY 4.0

الملخص

تُظهر النماذج اللغوية الكبيرة قدرات لافتة في معالجة المستندات وتحليل البيانات وتوليد الشيفرة، لكن توليد المعلومات المكانية بصيغة منظمة موحدة ما يزال تحديًا يحد من التكامل الإنتاجي. تقدم هذه الورقة معيارًا لتوليد المخرجات المكانية المنظمة والمنسقة من النماذج اللغوية، مع التركيز على تعزيز توليد المعلومات المكانية. ويُعرض سير عمل متعدد الخطوات لتحسين دقة وكفاءة توليد البيانات المكانية — يشمل توليد البيانات المكانية (مثل GeoJSON) وطريقة جديدة لفهرسة بنى شجرة-R. ويقارن المؤلفون الضبط الدقيق وهندسة الموجهات والتوليد المعزز بالاسترجاع (RAG) لتوليد المخرجات المنظمة، ويقترحون مقاييس ومجموعات بيانات جديدة، ويستخلصون إرشادات حول نقاط قوة كل منهج وقيوده للممارسين.

1. المقدمة والخلفية

لا تولد النماذج اللغوية صيغًا منظمة مثل JSON أو XML دون تعليم صريح. وتنقسم الحلول الحالية إلى ثلاثة مناهج: الضبط الدقيق [10]، والتوليد المعزز بالاسترجاع (RAG) [11]، وهندسة الموجهات [12]. فالضبط الدقيق لنموذج كبير مثل GPT-4 معقد وكثيف الموارد، لذا يستخدم العمل الموجه للمهام نماذج أصغر مثل TinyLLM؛ ويحسن RAG الدقة الواعية بالسياق لكنه يتطلب حوسبة إضافية وقد يحقن معلومات غير ذات صلة [11]، [15]؛ وهندسة الموجهات فعالة لكنها كثيفة العمل اليدوي وليست متسقة دائمًا [12]. ولم تكن توجد مقارنة شاملة لهذه المناهج للمخرجات المكانية المنظمة.

2. مجموعات البيانات

تنظم مجموعتا بيانات مُجمعتان التجارب: مجموعة منظمة عامة (JSON) ومجموعة مكانية منظمة (GeoJSON). وتغطي المجموعة المكانية معالم نقطية بخصائص مثل أسماء المحطات مع إحداثيات Easting/Northing وهندسة خطوط الطول/العرض — مثل محطات Brighouse وElland وHalifax وIllingworth وMytholmroyd وTodmorden — موفرة أهداف توليد واقعية على غرار الترميز الجغرافي.

3. المنهجية: الضبط الدقيق وRAG والموجهات وREL

للضبط الدقيق، تستخدم الدراسة تقنية التكيف منخفض الرتبة (LoRA) [10] مع تكميم 4-بت بخوارزمية GPTQ [41]: رتبة LoRA 8 (ألفا 16، إسقاط 0.1)، ومعدل تعلم 2e-4، واضمحلال وزن 0.001، ومعيار تدرج أقصى 0.3، على آلة Amazon SageMaker g5.xlarge. ولتجارب RAG وهندسة الموجهات يُستخدم نموذج GPT-4o-mini API كأساس، مع FAISS كمخزن متجهي يحمل عشرة أزواج أمثلة افتراضيًا. ويجمع منهج LLM المعزز بشجرة-R (REL) الجديد بين النماذج مضبوطة الدقة واسترجاع RAG والفهرسة المكانية بشجرة-R [16] — وهي طريقة GIS واسعة الاستخدام للاستعلام المكاني الفعال — فيلتقط النموذج العلاقات الهرمية والمكانية بصورة أفضل ويولد GeoJSON أكثر اتساقًا.

4. مقاييس التقييم

تُقترح ثلاث عائلات مقاييس: (1) التحقق المنظم من JSON — محاولة تحليل تحدد أخطاء الصياغة كالفواصل المفقودة، يليها تحديد الأخطاء؛ (2) تقييم المحتوى — سلالم تقييم قائمة على GPT تُجمع عبر المعايير؛ (3) تقييم أخطاء الصيغة. ويمدد تحديد الأزواج المشتركة ودرجات التشابه للأزواج غير المشتركة التقييم ليتجاوز المطابقة الدقيقة، منتجًا تجميع تشابه لكل زوج لقياس الجودة والاتساق الكليين.

5. التجارب والنتائج

عبر مجموعتي JSON العامة وGeoJSON، تقارن التجارب الضبط الدقيق وRAG وهندسة الموجهات وREL لتوليد JSON المنظم. فيكيف الضبط الدقيق النموذج مع دقائق المهمة المستهدفة لكنه مكلف حوسبيًا وذاكريًا؛ ويؤسس RAG المخرجات على سياق جغرافي مسترجع؛ وتوجه هندسة الموجهات الصيغة دون تحديث الأوزان؛ ويستفيد الهجين REL من التكيف الجغرافي مضبوط الدقة مع الاسترجاع وفهرسة شجرة-R لتحسين الاتساق الهرمي والمكاني لـ GeoJSON المولد. وتوضح الأمثلة المبلغ عنها (مخرجات llama3-7b وبأسلوب Paraloq على مجموعة المحطات) فروق النماذج في تسمية الخصائص ودقة الإحداثيات وبنية FeatureCollection.

6. الخاتمة

يدفع العمل توليد البيانات المكانية المنظمة بالنماذج اللغوية عبر المساهمة بمعيار ومقاييس ومجموعات بيانات جديدة ومنهج REL الذي يدمج الضبط الدقيق وRAG وفهرسة شجرة-R المكانية. وتمنح نتائجه الممارسين أساسًا دليليًا للاختيار بين الضبط الدقيق وRAG وهندسة الموجهات حسب حالة الاستخدام — موازنة بين جودة التكيف والكلفة الحوسبية وضمانات الاتساق والجاهزية الإنتاجية للتكامل الجغرافي المكاني.

Abstract

Large language models show remarkable capabilities in document processing, data analysis, and code generation, yet generating spatial information in a structured, unified format remains a challenge that limits production integration. This paper introduces a benchmark for generating structured and formatted spatial outputs from LLMs, with a focus on enhancing spatial information generation. A multi-step workflow is presented to improve the accuracy and efficiency of spatial data generation — including generating spatial data (e.g., GeoJSON) and a novel method for indexing R-tree structures. The authors compare fine-tuning, prompt engineering, and retrieval-augmented generation (RAG) for structured-output generation, propose new metrics and datasets, and derive guidance on the strengths and limitations of each approach for practitioners.

1. Introduction and Background

LLMs do not generate structured formats such as JSON or XML without explicit instruction. Current solutions fall into three approaches: fine-tuning [10], retrieval-augmented generation (RAG) [11], and prompt engineering [12]. Fine-tuning a large model such as GPT-4 is complex and resource-intensive, so task-oriented work often uses smaller models such as TinyLLM; RAG improves context-aware accuracy but demands extra computation and can inject irrelevant information [11], [15]; prompt engineering is effective but labor-intensive and not always consistent [12]. No comprehensive comparison of these methods for structured spatial output existed.

2. Datasets

Two collected datasets structure the experiments: a general structured (JSON) dataset and a spatial structured (GeoJSON) dataset. The spatial set covers point features with properties such as station names with Easting/Northing coordinates and longitude/latitude geometry — e.g., Brighouse, Elland, Halifax, Illingworth, Mytholmroyd, and Todmorden stations — providing realistic geocoding-style generation targets.

3. Methodology: Fine-Tuning, RAG, Prompting, and REL

For fine-tuning, the study uses the low-rank adaptation (LoRA) technique [10] combined with 4-bit quantization using the GPTQ algorithm [41]: LoRA rank 8 (alpha 16, dropout 0.1), learning rate 2e-4, weight decay 0.001, and max gradient norm 0.3, run on an Amazon SageMaker g5.xlarge machine. For RAG and prompt-engineering experiments the base model is the GPT-4o-mini API, with FAISS as the vector store holding ten example pairs as defaults. The novel R-tree enhanced LLM (REL) approach combines fine-tuned models with RAG retrieval and R-tree spatial indexing [16] — a widely used GIS method for efficient spatial querying — so the model better captures hierarchical and spatial relationships and generates more coherent GeoJSON.

4. Evaluation Metrics

Three metric families are proposed: (i) JSON structured validation — a parsing attempt flags syntax errors such as missing commas, followed by error identification; (ii) content evaluation — GPT-based rating scales aggregated across criteria; and (iii) format error evaluation. Common-pair identification and similarity scoring for non-common key pairs extend scoring beyond exact match, yielding per-pair similarity aggregation for overall quality and consistency measurement.

5. Experiments and Findings

Across the general JSON and GeoJSON datasets, the experiments compare fine-tuning, RAG, prompt engineering, and REL for structured JSON generation. Fine-tuning adapts the model to target-task nuances but is computationally expensive and memory-intensive; RAG grounds outputs in retrieved geospatial context; prompt engineering steers format without weight updates; and the REL hybrid leverages fine-tuned geospatial adaptation plus retrieval plus R-tree indexing to improve hierarchical and spatial consistency of generated GeoJSON. The reported examples (llama3-7b and Paraloq-style outputs over the station dataset) illustrate per-model differences in property naming, coordinate precision, and FeatureCollection structure.

6. Conclusion

The work advances LLM-based structured spatial data generation by contributing a benchmark, new metrics and datasets, and the REL method that fuses fine-tuning, RAG, and R-tree spatial indexing. Its findings give practitioners an evidence base for selecting among fine-tuning, RAG, and prompt engineering by use case — balancing adaptation quality, computational cost, consistency guarantees, and production readiness for geospatial integration.
