Beyond the Benchmark: A Customizable Platform for Real-Time, Preference-Driven LLM Evaluation

ما وراء المعيار: منصة قابلة للتخصيص لتقييم النماذج اللغوية اللحظي الموجه بالتفضيلات

👤 George Zografos, Lefteris Moussiades 📄 Electronics, 2025 · Vol. 14(13), 2577 🔗 10.3390/electronics14132577 ✓ CC BY 4.0

الملخص

تقيس المعايير الموحدة النماذج اللغوية العامة لكنها تُغفل معايير الجودة الخاصة بالمجالات، تاركةً تخصصات كثيرة دون أدوات منهجية لاختيار النماذج [15–21]. تقدم هذه الورقة إطار عمل LLM PromptScope (LPS)، وهو إطار تقييم لحظي قابل للتخصيص يُعرّف فيه المستخدمون معايير نوعية موائمة لمهامهم، مع آلية «النموذج اللغوي كحَكَم» — تستخدم عدة نماذج لغوية كمقيّمين — لتقليل التدخل البشري مع إدخال التفضيلات الذاتية.

تقارن التجارب على MMLU [45] وMATH [46] وHumanEval الترتيبات التقليدية بالتقييمات الموجهة بالتفضيلات عبر نماذج حديثة؛ وتُظهر الإحصاءات أن معايير المستخدم قد تُغيّر ترتيب النماذج بشكل كبير، ولا سيما في المهام المفتوحة حيث تقدم المعايير القياسية إرشادًا محدودًا.

1. المقدمة

تمتد النماذج اللغوية اليوم من الرعاية الصحية إلى الكتابة الإبداعية، لكن مقاييس المقاس الواحد لا تلتقط توقعات المستخدمين الدقيقة المعتمدة على السياق. فالأجنحة الموجهة للسلامة (HarmBench [1] وAgentHarm [3] وStrongREJECT [4]) ومسابر الوقائعية [2] ومعايير الصوت (AIR-Bench [5]) ودراسات متانة كسر الحماية [6] وأجنحة الشيفرات (CRUXEval [7] وBigCodeBench [8] وCrossCodeEval [9] وتدقيقات الصحة [10] وHumanEval [11]) يغطي كل منها شريحة — لكن لا شيء منها يتكيف مع تعريف المستخدم الخاص للجودة.

يسد LPS هذه الفجوة: إطار ديناميكي متمحور حول المستخدم يوائم التقييم مع احتياجات النشر، وهو قيّم خصوصًا حيث تغيب المعايير الناضجة، جامعًا بين المقارنة متعددة النماذج والتحكيم الموجه بالتفضيلات.

2. الأعمال ذات الصلة

تدفع أتمتة المعارك الثنائية (Auto-Arena [22]) ومنصات التفضيل البشري (Chatbot Arena [23]) وعدة التوجيه المرئية (ChainForge [24] وPromptChainer [27] والهندسة التفاعلية [26]) وبيئات التوجيه ومستودعاته (PromptTools [25] وPromptSource [29] وSelf-Instruct [30] وملاعب التجريب [28]) ومتتبعات الاستدلال (Chain-of-Thought Hub [16] ومجموعات الاستدلال العدائية [17] وSuperGLUE [18] وGLUE [19] وGPQA [20] وHotpotQA [21]) كل منها شظايا من التقييم — لكن لا شيء يجمع بين التحكيم اللحظي متعدد النماذج ومعايير مخصصة بالكامل من المستخدم، وهو موضع LPS.

3. البنية والتطوير

بُني LPS على HTML وCSS وPHP وAJAX وJavaScript وواجهات برمجة النماذج: توزع AJAX/PHP الطلبات غير المتزامنة على عدة مزودين، مما يمكّن التفاعل اللحظي جنبًا إلى جنب. وتشمل العائلات المقيّمة GPT-4o mini [36] وGemini 1.5 [37] وLlama 3.2 [38] وClaude 3.5 Sonnet [39] وMixtral [40] وQwen2.5 [41] وDeepSeek LLM [42].

يوجّه قلب «النموذج كحَكَم» الدليل نفسه المعرف من المستخدم إلى عدة نماذج حاكمة، ويجمع الدرجات ويُظهر الخلاف — مُبقيًا الجهد البشري في تصميم الدليل بينما تنتشر التفضيلات تلقائيًا عبر كل جولة تقييم.

4–5. التقييم وجولة دراسة الحالة

تُغذَّى عينات من MMLU [45] (المعرفة العامة) وMATH [46] (حل المسائل) وHumanEval (الشيفرة الوظيفية) تقييمات متوازية تقليدية مقابل موجهة بالتفضيلات؛ ويأتي سياق لوحات الصدارة من التتبع العام (LLM Stats [44] وArtificial Analysis [47] وMMLU-Pro [43]). والنتيجة الأبرز: إعادة وزن التفضيلات ترتيب النماذج الرائدة، وبحدة أكبر حيث تكون المعايير أقل إلزامًا.

تُظهر جولة LPS ذات التبويبات الخمسة — الاستقبال/اختيار النموذج، وساحة التوجيه، ومصمم المعايير، ولوحة التحكيم، والتصدير — للباحثين والممارسين إجراء تجارب التوجيه والمقارنات الموزونة بالتفضيلات واختيار النماذج عبر الواجهة من البداية إلى النهاية.

6. القيود

تخاطر النماذج الحاكمة بالتحيز والدائرية عندما تتشارك الحاكمة والمحكومة البنى ومدونات التدريب المعتمة؛ وتضيف معايير المستخدم ذاتية قد تعيق قابلية إعادة الإنتاج عبر المواقع. كما تحدّ تكلفة وزمن التحكيم اللحظي متعدد النماذج من قابلية التوسع.

7. الاستنتاجات والأبحاث المستقبلية

يحل LPS التوتر بين مجموعات البيانات الموحدة والحكم الخاص بالمجال: فالمقارنة متعددة النماذج مع التحكيم الموجه بالتفضيلات تمنح الممارسين مرونة مع صرامة حيثما تكون المعايير غير ناضجة. ويستهدف العمل المستقبلي معايرة تحيز الحكام ومستودعات مشاركة الأدلة ودراسات النشر الطولية.

Abstract

Standardized benchmarks measure general-purpose LLMs but miss domain-specific quality criteria, leaving many specialties without systematic model-selection tools [15–21]. This paper presents LLM PromptScope (LPS), a customizable real-time evaluation framework in which users define qualitative criteria aligned with their tasks and an LLM-as-a-Judge mechanism — using multiple language models as evaluators — minimizes human involvement while injecting subjective preferences.

Experiments on MMLU [45], MATH [46], and HumanEval compare conventional rankings with preference-driven assessments across state-of-the-art models; statistics show user-defined criteria can significantly shift model rankings, especially on open-ended tasks where standard benchmarks give limited guidance.

1. Introduction

LLMs now span healthcare to creative writing, yet one-size-fits-all metrics cannot capture nuanced, context-dependent user expectations. Safety-oriented suites (HarmBench [1], AgentHarm [3], StrongREJECT [4]), factuality probes [2], audio benchmarks (AIR-Bench [5]), jailbreak dura-bility studies [6], and code suites (CRUXEval [7], BigCodeBench [8], CrossCodeEval [9], correctness audits [10], HumanEval [11]) each cover slices — but none adapts to a user's own quality definition.

LPS fills this gap: a dynamic, user-centric framework aligning assessment with deployment needs, particularly valuable where mature benchmarks are absent, combining multi-model comparison with preference-driven judging.

2. Related Work

Peer-battle automation (Auto-Arena [22]), human-preference platforms (Chatbot Arena [23]), visual prompt toolkits (ChainForge [24], PromptChainer [27], interactive engineering [26]), prompt IDEs and repositories (PromptTools [25], PromptSource [29], Self-Instruct [30], playgrounds [28]), and reasoning trackers (Chain-of-Thought Hub [16], NLI adversarial sets [17], SuperGLUE [18], GLUE [19], GPQA [20], HotpotQA [21]) each advance fragments of evaluation — yet none fuses real-time multi-model judging with fully user-defined criteria, which is LPS's position.

3. Architecture and Development

LPS is built on HTML, CSS, PHP, AJAX, JavaScript, and LLM API endpoints: AJAX/PHP fan out asynchronous requests to multiple providers, enabling side-by-side real-time interaction. Evaluated families include GPT-4o mini [36], Gemini 1.5 [37], Llama 3.2 [38], Claude 3.5 Sonnet [39], Mixtral [40], Qwen2.5 [41], and DeepSeek LLM [42].

The LLM-as-a-Judge core routes the same user-defined rubric to several judge models, aggregates scores, and surfaces disagreement — keeping human effort to rubric design while preferences propagate automatically through every evaluation run.

4–5. Evaluation & Use-Case Walkthrough

Samples from MMLU [45] (general knowledge), MATH [46] (problem solving), and HumanEval (functional code) feed parallel conventional-vs.-preference evaluations; leaderboard context comes from public tracking (LLM Stats [44], Artificial Analysis [47], MMLU-Pro [43]). The headline finding: preference weighting reorders frontier models, most sharply where benchmarks are least prescriptive.

The five-tab LPS walkthrough — landing/model selection, prompting arena, criteria designer, judging dashboard, and export — shows researchers and practitioners running prompt experiments, preference-weighted comparisons, and interface-based model selection end to end.

6. Limitations

LLM judges risk bias and circularity when evaluator and evaluated share architectures and opaque training corpora; user-defined criteria add subjectivity that can hamper reproducibility across sites. Cost and latency of multi-model real-time judging also bound scale.

7. Conclusions and Future Research

LPS resolves the tension between standardized datasets and domain-specific judgment: multi-model comparison plus preference-driven LLM judging gives practitioners flexibility with rigor wherever benchmarks are immature. Future work targets bias calibration of judges, rubric-sharing repositories, and longitudinal deployment studies.
